📊 Approach & Query

Query Code


-- Query 8: Return rate and net sales summary by store
SELECT
    ds.store_name,
    ds.region,
    ROUND(SUM(CASE WHEN fs.quantity > 0 THEN CAST(fs.quantity AS DOUBLE) * dp.standard_price ELSE 0 END), 2) AS gross_revenue,
    ROUND(ABS(SUM(CASE WHEN fs.quantity < 0 THEN fs.return_amount ELSE 0 END)), 2) AS total_returns,
    ROUND(SUM(CASE WHEN fs.quantity > 0 THEN CAST(fs.quantity AS DOUBLE) * dp.standard_price ELSE 0 END) 
          + SUM(CASE WHEN fs.quantity < 0 THEN fs.return_amount ELSE 0 END), 2) AS net_revenue
FROM fact_sales fs
LEFT JOIN dim_store ds ON fs.store_id = ds.store_id
LEFT JOIN dim_product dp ON fs.product_id = dp.product_id
WHERE ds.store_name IS NOT NULL
GROUP BY ds.store_name, ds.region
ORDER BY net_revenue DESC

Query Description

Executed 8 analytical SQL queries joining fact_sales with dim_store and dim_product on store_id and product_id respectively. Revenue was computed as quantity × standard_price for positive quantity transactions (sales), excluding returns (negative quantity). Customer segment labels were normalised using CASE WHEN to harmonise variants like 'Prem'/'premium' → 'Premium', 'Bgt'/'BUDGET' → 'Budget', 'Std'/'standard' → 'Standard'.
